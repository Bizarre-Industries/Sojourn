## Conditions met before commit

### Security (high severity, must-fix)

- **EdDSA key handling tightened in ADR-0020.** Added "Key handling
  protocol" subsection: stdin pipe via `op read --no-newline | sign_update -f -`,
  no tempfile, no `--key-file`. Service-account token scoped read-only
  to single vault item. `unset OP_SERVICE_ACCOUNT_TOKEN` after
  signing. GitHub Actions `add-mask` directive applied.
- **`brew vulns` argv invocation in ADR-0021.** Added explicit step
  1: Process argv array, never shell-interpreted string. Brewfile
  path validated via `realpath` against `~/.config/sojourn/` or
  chezmoi source root. Path with shell-metacharacters fails closed.
- **OSV JSON parser caps in ADR-0021.** Added 16 MB response cap +
  depth 32 cap; reject on overflow.

### Architect (medium severity, addressed)

- **Auto-tap policy in ADR-0021.** Added step 2: probes
  `brew tap-info homebrew/brew-vulns`, prompts user consent before
  tapping, never silent. Aligns with CLAUDE.md invariant 7.
- **v0.2-plan.md L86 vs ADR-0019 contradiction reconciled.** Plan
  bullet updated to match ADR-0019: bundled-binary fast path
  authoritative, no formula-fallback `depends_on`.
- **ADR-0022 flip-condition #2 made falsifiable.** Replaced "user
  base demanding reproducibility has grown" with concrete
  GitHub-label-tracked criterion: 2 `repro-drift` issues within a
  30-day window.

### UX (medium severity, addressed)

- **Three-state freshness indicator in ADR-0021.** Added step 6 with
  `fresh`/`stale`/`unavailable` states + copy text per state +
  first-launch behavior. Step 7 covers OSV.dev rate-limit fallback.
- **Persisted `install_source` in ADR-0020.** Replaced brittle cache-
  glob detection with `prefs.toml:install_source` written once at
  first launch. Override available in Updates pref pane.

  list jobs hard-cap at 30s.

- **Migration UX for v0.1 packages.toml** (UX council). v0.1 was

  detection step in v0.2 step 5.
- **Bootstrap pane row for backend cask install latency** (UX
  council). Implementation detail of v0.2 step 8.
- **Sparkle appcast detached Task on launch+24h** (perf council).
  Implementation detail of step 8.
- **AppStore job log buffer cap (10k lines spill to disk)** (perf

- **Orphan formula on cask uninstall** (devil-advocate). Documented
  in ADR-0019 "Negative consequences" subsection; cask `zap` block

## Conditions rejected as theater / out-of-scope

- **Devil-advocate: defer ADR-0021 to v0.3.** Rejected — Advisories
  pane is in v0.2 sidebar; shipping a no-op surface is misleading.
  Real OSV-format implementation is the right call now.
- **Devil-advocate: keep ADR-0010 split.** Rejected — bus-factor
  case for mpm has weakened, brew bundle coverage is sufficient.
  Multi-machine homelab argument is reopened only via the
  ADR-0022 flip-condition mechanism.
- **Devil-advocate: lessons.md entries missing.** Verified false
  alarm — `lessons.md` contains all referenced entries
  (`Drop Nix as a "Phase 2 mode"`, `Drop mpm for brew bundle`,
  `Real Liquid Glass needs glassEffect`, etc.). Devil-advocate
  agent's grep was misled by a stale memory observation.

## Risks acknowledged but not blocking

- ADR-0020: GitHub Pages appcast host = single point of failure for
  availability. EdDSA protects integrity, not availability.
  Acceptable for personal/homelab tool.
- ADR-0021: 24h cache TTL means fresh CVE invisible until next
  scheduled scan. Manual scan via UI re-runs subprocess and
  bypasses cache.
- ADR-0018: No automated v0.1→v0.2 packages.toml migration tool.
  Acceptable given v0.1 was alpha-only.
