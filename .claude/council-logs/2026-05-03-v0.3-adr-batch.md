# Council deliberation — v0.3 ADR batch

- **Date**: 2026-05-03
- **Trigger**: 4 new ADRs created (0023, 0024, 0025, 0026) per
  CLAUDE.md trigger list ("Creates a new ADR").
- **Mode**: Single batch deliberation (4 ADRs share the v0.3 plan
  rationale per `docs/process/plans/v0.3-plan.md`; firing council 4
  separate times would be theater per lessons.md).
- **Members**: council-architect, council-security,
  council-devil-advocate, council-perf-skeptic, council-ux-critic —
  fired in parallel.

## Verdict

**APPROVE-WITH-CONDITIONS** (5/5 members, unanimous on conditional
approval).

All 5 members returned substantive Dissents. Council not theater.
Devil-advocate brought the strongest contrarian case on ADR-0025
(defer Sparkle delta to v0.4); rejected because maintainer locked
v0.3 inclusion in `v0.3-plan.md` §"Hard decisions" line 83-84,
re-litigation requires plan amendment (not council scope).

## Conditions met before commit

### Security (high severity, must-fix)

- **ADR-0024 literal `SMAuthorizedClients` requirement string.** Added
  "Signing & embed protocol" sub-section spelling out the exact
  Developer ID requirement string template with `<TEAMID>` placeholder
  for substitution at build time. Without this, an implementer
  guessing `anchor apple generic` alone would produce a string that
  accepts any notarized macOS app as a root proxy.
- **ADR-0024 per-connection XPC validation mandated.** Added text
  requiring `NSXPCConnection.setCodeSigningRequirement(_:)` (macOS
  13+) on the helper's listener, with explicit note that
  `SMAuthorizedClients` is install-time-only and does NOT gate XPC
  connections. Closes the privilege-escalation hole where any local
  process discovering the mach name could call into the helper.
- **ADR-0024 argv-injection closed at the API contract.** Added
  constraint: App Store IDs cross XPC as `UInt64`, never `String`;
  helper rejects values that fail `UInt64(stringValue)` round-trip;
  `Process` invoked with `arguments: ["install", String(id)]` (argv
  array, never concatenated string). Matches CLAUDE.md threat-list
  prohibition on shell-interpreted strings.
- **ADR-0024 AuthorizationServices semantics corrected.** Original
  text conflated install-time `SMAppService.register()` Touch-ID
  prompt with per-call `AuthorizationCopyRights` semantics. Rewritten:
  Touch-ID prompt fires once at helper-install time; subsequent `mas`
  calls go through XPC with `SMAuthorizedClients` + per-connection
  code-signing validation only, no per-call prompt, until helper is
  uninstalled or user revokes via System Settings.
- **ADR-0025 Sparkle 2 fallback claim weakened.** "Apply-failure
  fallback is automatic in Sparkle 2" rewritten as
  delegate-callback-based explicit fallback per
  `SPUUpdaterDelegate.updater(_:didAbortWithError:)` on
  `SUErrorCode.deltaUpdateFailed`. SparkleService implements the
  explicit retry. Smoke test for delta-corruption path added to
  step 6 exit criteria (intentionally bad delta on Tahoe VM).

### Architect (medium severity, addressed)

- **ADR-0024 "Signing & embed protocol" sub-section.** Names the
  helper's bundle path inside `Sojourn.app`
  (`Contents/Library/LaunchDaemons/`), codesign invocation order in
  `notarize.yml` (helper signed before app embed; outer app re-signed
  after; both pass `spctl --assess --verbose=4` independently).
- **ADR-0026 vs v0.3-plan force-take-writer reconciled.** Plan line
  60 listed three options including `force-take-writer`. ADR rejects
  it explicitly in Alternatives section (`force-take-writer` is
  lock-stealing distinct from force-push, but still violates
  invariant 6 by allowing a Mac to grab `.sojourn/active.toml`
  without acknowledging in-flight remote work). Plan line 60 amended
  to `pull-rebase / pull-merge / abort`.
- **ADR-0023 socket-probe rejection rewritten.** Original rejection
  cited TCC permission for `/var/run/docker.sock`; technically wrong
  (unix socket reads don't trigger TCC for non-sandboxed apps).
  Rewritten: socket probing tests daemon liveness, not installation;
  the pane's job is to surface installed runtimes regardless of
  running state.

### UX (medium severity, addressed)

- **ADR-0024 helper authorization status surface.** Added
  PackagesPane status row "Touch-ID authorization active" with
  "Revoke" button calling `AuthorizationFree`. Closes the
  surveillance-regression UX gap (post-v0.2, mas calls now fire
  silently — user must have visibility + revoke path).
- **ADR-0026 copy spec sub-section.** Exact button strings:
  "Pull and rebase your work" / "Pull and merge" / "Cancel — leave
  local alone". Push-blocked surface: "Push blocked. Pull <N>
  commits first or cancel the pull-pending state in Sync." Modal
  state sticky (re-opening SyncPane re-presents same conflict until
  resolved). `abort` internal name unchanged for ConflictResolver
  state-machine clarity; user-facing label is "Cancel — leave local
  alone."
- **ADR-0026 cross-pane conflict-pending visibility.** Sidebar shows
  small badge on Sync entry when conflict-pending; OverviewPane
  surfaces it as a status row. Mirrors v0.2 advisory three-state
  freshness pattern.
- **ADR-0023 empty + edge states.** Zero-installed: single CTA
  "Install via Brewfile" linking to PackagesPane. Never-launched
  runtime: "Not yet launched" placeholder. Badge accessibility
  label distinct from visual ("Active runtime: Docker Desktop") for
  VoiceOver — color alone cannot carry active state.
- **ADR-0025 user-visible delta-apply fallback.** SparkleService
  delegate hook surfaces "Update download restarting (delta
  unavailable)" string when fallback triggers. Confirms Sparkle 2
  delegate API exposes the failure for custom messaging.

### Perf-skeptic (medium severity, addressed)

- **ContainersService perf condition recorded in ADR-0023.** Five
  version-probe subprocesses run with `async let` parallelism inside
  the actor (not sequential await); filesystem-presence
  short-circuits the version probe (binary not in candidate dirs →
  "not installed" without spawning); result memoized for AppStore
  lifetime; refresh ONLY on user gesture or BootstrapCoordinator
  invalidation (no timer-based re-probe). 5s timeout per version
  probe (advisory tier).
- **`GitService.inboundCommits(since:)` capped in ADR-0026.** Hard
  cap at 200 commits via `--max-count=200` on the underlying
  `git log` argv. Parsing happens in GitService actor, never in
  view body. SyncPane uses `LazyVStack` / `List` with `id: \.sha`
  (not `VStack` + `ForEach`).
- **`git fetch` cadence in ADR-0026.** Fires on user "Pull" gesture
  or cooldown-elapsed background sync only — NOT on every SyncPane
  appearance. `git rev-list --count` runs first as cheap count
  check; skip the heavy parse if count is 0.
- **MasHelper subprocess timeout (ADR-0024).** Helper-side 600s
  hard cap on `mas install` / `mas upgrade` (snapshot tier alignment
  per JobRunner timeout policy). Returns `MasError.timedOut` to XPC
  client on hang; AuthorizationRef stays valid for next call.
- **Sparkle init detached (ADR-0025).** `SPUStandardUpdaterController`
  initialized in `Task.detached` so it does not block menubar
  appearance (200ms launch budget per v0.2 perf baseline). Appcast
  fetch timeout set to 30s explicitly (Foundation default 60s too
  lenient).

### Devil-advocate (high-strength dissent on ADR-0025, rejected as out-of-scope)

- **ADR-0025 defer to v0.4** — devil-advocate's strongest case.
  Rejected because maintainer locked v0.3 inclusion in
  `v0.3-plan.md` §"Hard decisions" line 83-84. Re-litigation
  requires plan amendment, not council scope. Devil-advocate's
  underlying concern (delta-apply path untestable before v0.3.0
  ships, since v0.3.0 has no predecessor) is real and addressed by
  the smoke-test condition above (intentional delta-corruption on
  v0.3.0 → v0.3.1-rc dev build before tagging v0.3.0 production).
- **ADR-0023 OrbStack-first priority** — devil-advocate argued the
  hardcoded "Docker > OrbStack" priority misreports the
  daily-driver case. Maintainer locked Docker-first priority in
  `v0.3-plan.md` §"Hard decisions". OrbStack docker-shim
  impersonation hazard (a stale `/Applications/Docker.app` with
  OrbStack as actual daemon) acknowledged in ADR-0023 Negative
  consequences as a v0.3 read-only acceptable limitation; v0.4
  must resolve before any write actions.
- **ADR-0026 always-pull-rebase silent** — devil-advocate argued
  the three-button modal is over-engineered for the single-author
  fleet (maintainer pushing to own remote from own machines).
  Steelmanned in ADR-0026 Alternatives; rejected because the
  multi-machine value prop in `v0.3-plan.md` §"Why explicit
  conflict UX" specifies user-visible inbound-commit list, and
  silently rebasing hides the "your laptop pushed 3 commits while
  you were away" surface that justifies the feature.
- **`GitService.inboundCommits(since:)` as private extension** —
  devil-advocate argued promoting to public Service API fires
  council unnecessarily. Acknowledged but rejected: ConflictResolver
  is a separate file in `Sojourn/Sync/` that genuinely needs the
  GitService method; calling through internal-only would require
  compromising actor boundaries. Council fires once on the
  GitService addition (batched into the same commit as the
  resolver per devil-advocate's framing).

## Conditions deferred to implementation step (documented as TODOs)

- **ADR-0024 cert-rotation path** (security, medium). Developer ID
  Application certificate has 5-year cycle; renewal requires
  re-shipping the pinned `SMAuthorizedClients` requirement string
  in the next release. Document the recovery path in
  `docs/how-to/operate/cert-rotation.md` during step 4 (helper
  implementation), not in the ADR itself.
- **ADR-0024 dev-mode bypass** (security, medium).
  Certificate-pinning means Debug builds (unsigned or
  differently-signed) cannot test the helper path locally. Step 4
  must specify a Debug-only path that skips the requirement check
  with an OSLog warning, controlled by a debug-only build flag.
- **ADR-0025 cached-DMG re-verification** (security, medium).
  Workflow re-verifies cache-restored prior DMG via
  `spctl --assess --verbose=4` and `codesign --verify --deep
  --strict` before feeding to `generate_appcast`. Implement in
  step 6, not in the ADR.
- **ADR-0025 `actions/cache` → `gh release download`** (devil-
  advocate, medium). Replace `actions/cache` with
  `gh release download <previous-tag>` for delta predecessor;
  cache is not durable, GitHub Releases is. Implement in step 6.
- **ADR-0025 Sparkle pinned to exact version** (devil-advocate,
  medium). `Package.swift` uses `exact: "2.6.x"` (not `from:`);
  bump explicitly with council fire per CLAUDE.md trigger.
  Implement in step 6.
- **ADR-0026 rebase-mid-failure recovery state** (security,
  medium). State machine adds 6th state
  `rebase-aborted-on-conflict` exposing "Abort rebase and revert
  to pre-pull state" action running `git rebase --abort`.
  Implement in step 5.
- **ADR-0024 first-install onboarding row** (UX, low). BootstrapPane
  shows a row "Setting up App Store install helper — needs admin
  password once" before the Authorization Services prompt fires.
  Implement in step 4.
- **ADR-0023 last-launched timestamp source** (architect, medium).
  ADR mitigation mentions "version + last-launched timestamp"
  per row but APFS atime is unreliable per lessons.md. Step 2
  implementation: drop the timestamp from the row OR source it
  from `launchctl print system/com.docker.docker | grep last exit`
  for daemons + `mdls -name kMDItemLastUsedDate <app>` for `.app`
  bundles, with fallback to "—" when unknown.
- **All four ADRs localization extraction** (UX, low). UI strings
  use `String(localized:)` per CLAUDE.md coding-style; no
  hardcoded `Text("...")` in pane code. Implementation steps
  enforce.
- **Council fatigue mitigation** (devil-advocate, medium). Council
  will fire on every helper change, every signing change, every
  notarize.yml change across stages 4 + 6 + 8. Recommend batching
  council fires per implementation stage (one fire per stage 4,
  5, 6) rather than one fire per commit. Documented for future
  reference.

- **Security agent claim that ADR-0020 missing on disk.** Verified
  false alarm — `docs/decisions/0020-sparkle-plus-cask-hybrid-update.md`
  exists with the "Key handling protocol" subsection. Security

- **Devil-advocate ADR-0026 auto-merge with conflict markers** —

## Risks acknowledged but not blocking

- **CRITICAL → mitigated.** Privilege escalation via missing
  per-connection XPC validation (security risk #1) closed by the
  `setCodeSigningRequirement` mandate in ADR-0024 amendment.
- **CRITICAL → mitigated.** Wildcard requirement-string accepting
  any Apple-signed binary (security risk #2) closed by literal
  template + identifier pin in ADR-0024 amendment.
- **HIGH → mitigated.** Argv injection on `mas install <id>`
  (security risk #4) closed by `UInt64` type constraint at XPC
  boundary in ADR-0024 amendment.
- **HIGH → deferred to step 6.** Sparkle private key leak via
  missing protocol citation (security risk #3) — ADR-0020 cite
  verified valid; key handling protocol intact.
- **MEDIUM.** OrbStack docker-shim impersonation in ContainersService
  detection (architect risk + devil-advocate). v0.3 read-only —
  UX confusion only. v0.4 write actions over this signal must
  resolve via socket-based liveness probe.
- **MEDIUM.** Sparkle delta-apply corruption surface for users on
  metered connections who explicitly chose delta path
  (ux-critic risk). Telemetry path not in scope; manual
  troubleshooting doc required for v0.3 release.
- **MEDIUM.** User clicks "Pull and rebase" with uncommitted
  Brewfile edits. ConflictResolver state-machine entry
  `rebase-aborted-on-conflict` covers (deferred to step 5
  implementation).
- **MEDIUM.** User revokes helper authorization mid-fleet-install.
  Helper XPC connection drops; partial install state on disk.
  ConflictResolver pattern reused — surface partial state in
  PackagesPane row, allow user to retry. Documented for step 4.
- **LOW.** Lima/Colima fixture maintenance burden if either
  project changes `--version` output format. Acceptable; matches
  existing precedent.
