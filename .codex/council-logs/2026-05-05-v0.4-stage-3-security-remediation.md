# Council Log: v0.4 Stage 3 Security Remediation

Date: 2026-05-05

## Trigger

Council fired because Stage 3 touches MAS privileged-helper trust, signing
requirements, Info.plist signing metadata, and ADRs for helper/security
behavior. The review scope is the Stage 3 diff only; the pre-existing
`AGENTS.md` dirty edit is explicitly out of scope and must not be staged.

## Final Diff Under Review

- Bumped `CURRENT_PROJECT_VERSION` from 30 to 31 and regenerated
  `Sojourn.xcodeproj`.
- Hardened MAS helper trust by pinning app/helper code-signing requirements to
  Team ID, failing release builds closed when `DEVELOPMENT_TEAM` is absent, and
  validating the original and resolved `mas` path before privileged execution.
- Surfaced untrusted MAS helper state in `MasService` and Packages UI, blocking
  MAS install/upgrade until a root-owned non-writable executable is available.
- Hardened Homebrew bootstrap installer checks by pinning the expected
  Developer ID Installer Team ID and notarization trust output.
- Hardened secret scanning by using the bundled gitleaks config, current
  `gitleaks dir` CLI shape, `--report-path -`, bounded JSON capture, fixed
  default-rule extension, AWS capture grouping, and additional high-confidence
  provider rules.
- Split pull from apply for remote sync state. Pulled chezmoi scripts,
  templates, `.chezmoitemplates` contents, parsed install-capable Brewfile rows,
  and unparsed Brewfile Ruby now pause for explicit review before apply/install.
- Bound reviewed apply to a content fingerprint and block fresh pull/push while
  review is pending or apply is running.
- Added Sync UI, menu, and toolbar states for pending pull-apply review,
  applying reviewed changes, cancellation, and bounded review previews.
- Added regression coverage for MAS trust, installer signature pinning,
  gitleaks invocation/config behavior, subprocess output limits and
  cancellation, pull-apply review, templates, Brewfile Ruby, fingerprint
  mismatch, and UI accessibility identifiers.
- Updated ADRs, threat-model/security docs, `CHANGELOG.md`, `open-questions.md`,
  and `lessons.md`.

## Council Votes

### Architect

Decision: Approve with conditions.

Conditions:
- The pull/apply split must be reflected in ADR-0026, not only source code.
- The reviewed apply must be bound to the exact pulled content so a local edit
  cannot change what is applied after the user approves.
- The pending review state must block a second pull or push.

Resolutions:
- ADR-0026 now documents the v0.4 pull-apply review amendment, including
  scripts, templates, Brewfile entries, unparsed Brewfile Ruby, fingerprint
  binding, and pending-state behavior.
- `PullApplyReview` stores a SHA-256 content fingerprint over scripts,
  templates, and full Brewfile contents; `applyReviewedPull()` recomputes it
  before running destructive apply/install work.
- `pull()` and `push()` return early while `awaitingPullApplyReview` is active,
  and reviewed apply switches to an active applying phase immediately.

### Security

Decision: Approve with conditions.

Conditions:
- Root helper execution must not trust user-writable Homebrew paths.
- Release XPC trust must fail closed without an expanded Team ID.
- Secret scanning must cover current gitleaks defaults plus Sojourn's
  high-confidence provider rules and must not silently accept malformed or huge
  JSON output.

Resolutions:
- `MasExecutableValidator` validates original path components, resolved path
  components, final file type, root ownership, write bits, and executable bit.
  The helper returns a distinct untrusted-tool sentinel, and the app preflights
  before XPC install/upgrade.
- Main app and helper plists carry the expected Team ID value. Release
  code-signing requirement construction fails closed when that value is missing
  or unexpanded.
- `SecretScanService` passes `--report-path -`, uses the bundled config
  explicitly, removes stale `dir --no-git`, limits captured JSON, and blocks
  fine-grained GitHub PATs plus Slack bot tokens. The bundled config now extends
  default rules correctly and smoke-tested against live gitleaks output.

### Devil's Advocate

Decision: Approve with conditions.

Conditions:
- Chezmoi templates and Brewfile Ruby must be considered executable review
  inputs, not only `run_` scripts and parsed package rows.
- App Store install copy must be honest when the helper is registered but the
  `mas` binary is intentionally rejected.

Resolutions:
- Review discovery now includes `.tmpl` files, files under
  `.chezmoitemplates`, and nonblank/non-comment Brewfile lines that the parser
  cannot safely classify.
- PackagesPane reports "App Store installs disabled" with recovery copy for a
  trusted root-owned `mas` path while preserving the existing helper
  registration/approval states.

### Perf Skeptic

Decision: Approve with conditions.

Conditions:
- Pull-review discovery must not block the main actor for large dotfile repos.
- UI previews must be bounded.
- Subprocess output limits must terminate runaway direct children.

Resolutions:
- Review building runs in a cancellable detached task, stores only bounded
  previews, and records omitted counts.
- SyncPane displays review sections inside a bounded scroll region.
- `SubprocessRunner` drains stdout/stderr with per-stream limits, sends
  SIGTERM when exceeded, and preserves SIGTERM/SIGKILL cancellation escalation.

### UX Critic

Decision: Approve with conditions.

Conditions:
- Pending pull-apply review must be visible from the main window, toolbar, and
  menu bar.
- Applying reviewed changes needs visible progress and cancellation affordance.
- Review copy must name what will happen without implying automatic cleanup.

Resolutions:
- `MainWindowView`, `MenuBarRootView`, and `SyncPane` now expose pending review,
  applying reviewed pull, and cancellation states.
- SyncPane lists scripts, templates, packages, and reasons with omitted counts,
  then requires an "Apply Listed Changes" confirmation.
- Recovery copy distinguishes leaving pulled data unapplied from retrying or
  rolling back.
