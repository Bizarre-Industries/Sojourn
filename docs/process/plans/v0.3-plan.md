## Why (one paragraph each)

**Why ship Containers panel.** Sojourn's value prop is "carry your
Mac config" — for any developer-adjacent user, Docker / OrbStack /
Apple `container` config is part of that surface. Detection +
"installed via" classification + per-tool toggle is straightforward
work that the v0.2 deferral was just timeline pressure.

**Why privileged-helper Touch-ID.** v0.2's
`osascript with administrator privileges` flow prompts for a password
on every `mas install`. Per-install prompts are hostile UX for users
maintaining multi-machine fleets. A privileged helper installs once
+ asks once; afterward all `mas install` / `mas upgrade` calls go
through the helper without re-prompting until reboot.

**Why Sparkle delta updates.** Full-DMG every release at ~30-80 MB ×
monthly cadence is ~600 MB/year/user. Delta updates (`bsdiff` against
the last release) typically run 4-8 MB. Wins for users on metered
connections + cuts CDN costs. CI complexity is bounded — Sparkle
already ships `generate_appcast` which handles delta generation
against a local archive of prior DMGs.

**Why explicit conflict UX.** ADR-0012's cooperative writer lock
prevents simultaneous push, but v0.2 lacks UX for "you have local
commits + remote moved while your Mac was asleep." The current
refuse-and-error path just bubbles git's stderr to the user — opaque.
A proper conflict modal listing inbound commits + suggested actions
(pull-rebase / pull-merge / force-take-writer) is small but
load-bearing for the multi-machine value prop.

## Hard decisions (locked, don't relitigate)

Carried from v0.2:

- macOS 26 Tahoe deployment floor.
- Single backend: brew bundle.
- No `Backend` protocol.
- `prefs.toml:install_source` for cask vs DMG detection.
- Sparkle EdDSA key at `op://Bizarre-Industries/sojourn-sparkle-eddsa`.

New for v0.3:

- **Containers detection priority**: Docker Desktop > OrbStack >
  Apple `container` CLI > Lima > Colima. (User decision: Docker is
  the underlying daemon; OrbStack is a faster runtime over Docker's
  protocol.)
- **mas Touch-ID helper architecture**: privileged helper at
  `/Library/PrivilegedHelperTools/industries.bizarre.Sojourn.helper`,
  installed via `SMAppService` (post-macOS 13 path); uninstalled via
  cask uninstall hook. (User decision: option (a), privileged
  helper.)
- **Sparkle delta updates ship in v0.3.0** — promoted from v0.3
  deferred to v0.3 in-scope.
- **Multi-machine conflict UX**: refuse-and-show-diff (option b).
  Pull/resolve must complete before push is allowed. UI surfaces
  inbound commits in the Sync pane.
- **`repro-drift` issue template lives in the user's data/dotfiles
  repo**, not Sojourn's source. Sojourn ships the template as a
  reference at `.github/ISSUE_TEMPLATE/repro-drift.md` for users to
  copy via the "setup new dotfiles repo" flow.
- **Skip v0.1 packages.toml migration.** v0.1 was alpha-only with no
  users at risk. Drop the migration UX from the v0.2 council deferral
  list.
- **JobRunner timeout policy**:
  - install / upgrade jobs: timeout-exempt (cancellable only).
  - advisory / list / dump jobs: 30s hard cap.
  - snapshot create / restore: 600s hard cap.

## Council triggers (recap — full list in `.claude/agents/README.md`)

Council automatically fires on:

- New ADR creation (any).
- New external dependency added (Brewfile, `Package.swift`, GitHub
  Actions workflow).
- Breaking change to a `Service` actor's public API or a
  persisted-on-disk schema (Brewfile format, generations tarball
  schema, `cooldowns.toml`, `prefs.toml`, `machines.toml`).
- Code deletion >100 lines in one commit.
- Any change under `Sojourn/Secrets/`, `Sojourn/Policy/`, signing
  configuration, or notarization workflow.

Everything else: a single `self-critique` subagent runs on the diff
before commit.

## Don't

- Don't reintroduce `Backend` protocol "in case Nix comes back" (per
  ADR-0022 flip-conditions; not yet met).
- Don't attempt the privileged helper without a Touch-ID
  authorization grace period — the helper must NOT bypass user
  consent for `mas install`, just suppress the per-install password
  prompt within a session.
- Don't ship Sparkle delta updates without an end-to-end test
  exercising the v0.3.0 → v0.3.1 sandbox VM apply path. Delta math
  errors corrupt the bundle; full-DMG fallback must trigger on
  delta-apply failure.
- Don't add Containers panel write actions in v0.3. Read-only
  detection + display only. v0.4 might add "start container" /
  "stop daemon" actions.
- Don't break the cask `caveats` block when bumping versions via
  `brew bump-cask-pr`. Caveats live in the formula source; bumps
  preserve them by default but verify on each release.

## Verification rule (read this before every external claim)

Whenever a step would rely on a third-party tool's current behavior,
flag set, or availability — fetch the upstream docs / release notes
before relying on it. Specifically:
[Sparkle 2.x docs](https://sparkle-project.org/documentation/),
[Apple `container` CLI](https://github.com/apple/container),
[OrbStack docs](https://docs.orbstack.dev/),
[`SMAppService` reference](https://developer.apple.com/documentation/servicemanagement/smappservice),
[`mas` releases](https://github.com/mas-cli/mas/releases).

LLM-generated code that compiles and "looks right" can still be
wrong. After writing code that calls an external API, framework, or
system service: write a minimal smoke run BEFORE moving to the next
task.
