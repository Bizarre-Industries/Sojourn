## What this is

v0.4 is the native UI reset. v0.3 completed release-blocking service
and notarization work, but the app still reads like a branded prototype:
hero copy, custom cards, hard-coded placeholder panes, black midlists,
two-letter chips, and v0.2/v0.3 future-tense copy. v0.4 turns Sojourn
into a quiet macOS utility: native split-view structure, standard
toolbar actions, dense operational surfaces, and panes backed by the
service primitives that already exist.

## Why

**Why reset UI before adding more backend scope.** The current interface
makes real shipped functionality harder to trust because it mixes
operational controls with marketing-style chrome and stale placeholder
promises. v0.4 should make the app boring in the right way: clear
status, explicit refresh/pull/push actions, native lists/tables, and no
future-tense copy for work already shipped.

**Why native macOS utility, not another visual theme.** Sojourn is a
tool users may leave open while changing machine state. Familiar macOS
navigation, semantic colors, system typography, and compact toolbars
reduce surprise and make destructive or privileged actions easier to
review. The reset should remove visual noise before adding new write
actions.

## Hard Decisions

- The first viewport is the app, not a hero. No marketing headline,
  slogan block, giant brand lockup, or card-heavy dashboard.
- Keep the 11-pane navigation model from v0.3.
- Preserve pane accessibility identifiers:
  `pane.overview`, `pane.packages`, `pane.containers`,
  `pane.generations`, `pane.macos-features`, `pane.preferences`,
  `pane.sync`, `pane.machines`, `pane.advisories`, `pane.jobs`,
  `pane.settings`.
- Use `NavigationSplitView`, grouped native sidebar rows, `@SceneStorage`
  selection, system typography, semantic colors/materials, and a compact
  toolbar for refresh / pull / push / status.
- UI still never calls `Process` directly. Views read `AppStore` and
  dispatch to existing store/service entry points.
- Stage 1 preserves old visual primitives unless removing them stays
  under the 100-line deletion council threshold. Cleanup can be a later
  mechanical or council-gated commit.

## ADRs

## Source Code: File-by-File Changes

### Rewrite

- `Sojourn/UI/MainWindowView.swift` — native grouped sidebar, scene
  storage selection, compact toolbar, standard navigation title behavior.
- `Sojourn/UI/Panes/OverviewPane.swift` — compact operational dashboard:
  package counts, sync state, container status, update status, recent
  jobs/history.
- `Sojourn/UI/Panes/PackagesPane.swift` — native list/table layout for
  manager summaries. Remove black custom midlist and two-letter chips.
- `Sojourn/UI/Panes/ContainersPane.swift` — native runtime list/table
  with installed/version/active status and explicit rescan.
- `Sojourn/UI/Panes/GenerationsPane.swift` — list
  `GenerationService.list()` output with archive size, SHA prefix, note,
  and empty/error states.
- `Sojourn/UI/Panes/MacOSFeaturesPane.swift` — useful feature rows from
  existing `MacOSFeaturesService` primitives or honest read-only
  capability rows when write paths are not present.
- `Sojourn/UI/Panes/PreferencesPane.swift` — searchable domain corpus
  from `PrefService.loadDomainCorpus()`, with layer/syncable/access
  affordances.
- `Sojourn/UI/Panes/AdvisoriesPane.swift` — current advisory snapshot,
  tap-missing state, and explicit refresh surface.
- `SojournUITests/SojournUITests.swift` — keep every sidebar pane smoke
  test, add checks for native toolbar/sidebar identifiers.

### Modify As Needed

- `Sojourn/Store/AppStore.swift` — add narrow snapshot vars only when a
  pane cannot read existing data without new UI-owned state. Avoid
  service API churn in stage 1.
- `Sojourn/Policy/AdvisoryService.swift` — out of scope for stage 1.
  Any later change under `Sojourn/Policy/` is council-gated.
- `Sojourn/UI/Panes/PaneHero.swift` and old visual atoms — leave in place
  during stage 1 if deletion would exceed 100 LOC.

## Execution Order

1. **Stage 1: Native UI reset.**
   Exit: the app launches with grouped `NavigationSplitView`, compact
   toolbar, native pane surfaces, preserved accessibility identifiers,
   no v0.3 future-tense placeholder copy, `swift build`, `swift test`,
   Xcode unit tests, and UI smoke tests updated for the reset.
2. **Stage 2: Pane data completion.**
   Exit: Generations, Preferences, Advisories, Packages, and Containers
   panes render all data already available from services without fake
   rows.
3. **Stage 3: UI polish and accessibility.**
   Exit: light/dark screenshots pass, VoiceOver labels cover toolbar and
   table actions, and no text overlaps at the minimum window size.
4. **Stage 4: Lint cleanup on touched UI.**
   Exit: touched UI files pass SwiftLint/format where local config
   permits; broad historical lint remains separate unless intentionally
   scoped.
5. **Stage 5: Release hardening.**
   Exit: repeat v0.3 release gates and verify Sparkle/cask behavior for
   v0.4.0.

## Acceptance Criteria for v0.4

- `make ci-local` passes.
- `swift build` passes.
- `swift test` passes.
- `xcodebuild test -project Sojourn.xcodeproj -scheme Sojourn
  -destination 'platform=macOS' -only-testing:SojournTests` passes.
- Full UI tests pass on a machine with a real Apple Development signing
  identity; unsigned local loader failures are not release evidence.
- Manual launch/screenshot pass in light and dark mode.
- All 11 sidebar panes load and keep their accessibility identifiers.
- No active pane says that future v0.3 work remains.
- No UI card inside another UI card; repeated-item cards only where a
  native list/table is not appropriate.
- No custom black midlist or two-letter package/container chips.
- No UI view calls `Process` directly.

## Council Triggers

Council fires on the standard list from `AGENTS.md` / `CLAUDE.md`:

- New ADR.
- New external dependency, including MCP servers.
- Breaking `Service` actor public API or persisted schema change.
- Deleting more than 100 LOC in one commit.
- Touching `Sojourn/Secrets/`, `Sojourn/Policy/`, signing config, or
  `notarize.yml`.

Everything else gets a `self-critique` before commit.

  crosses the council deletion threshold.
- Do not hide missing data behind fake demo rows.
- Do not move subprocess work into views.
