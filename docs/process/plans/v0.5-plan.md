# Sojourn v0.5 Plan

Status: **active**. Author: Codex after v0.4 verification.
Reader: Codex / Claude Code, autonomous. Execute top-to-bottom unless a
council vote says otherwise.

## What this is

v0.5 closes the smallest post-v0.4 product gap from the v0.4 open
questions: a native **Open Sojourn at login** control. v0.4 made the app
feel like a quiet macOS utility; v0.5 lets users keep that utility ready
after sign-in without hand-editing Login Items.

## Scope

- Add a narrow `LoginItemService` over `SMAppService.mainApp`.
- Surface login-item status in `AppStore`.
- Add a General Settings toggle for launching Sojourn at login.
- Show the macOS approval state explicitly when System Settings approval
  is required.
- Cover the AppStore toggle/status path with unit tests using a fake
  login-item service.

## Non-goals

- No background agent or LaunchAgent.
- No privileged helper changes.
- No new persistence schema; macOS owns Login Item state.
- No version tag until a verified release artifact exists.

## Acceptance Criteria

- `make build` passes.
- `make test` passes.
- `make leaks` passes.
- Xcode unit tests pass for `SojournTests`.
- General Settings includes `settings.openAtLogin` and
  `settings.loginItemStatus` accessibility identifiers.
- UI code does not call `SMAppService` directly.
